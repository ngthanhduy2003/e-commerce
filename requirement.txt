## 1. ĐÁNH GIÁ SƠ BỘ & PHÂN TÍCH YÊU CẦU

### 1.1 Tóm tắt yêu cầu từ Email khách hàng

Khách hàng cần:

- Backend API cho e-commerce
- Không cần UI
- Ưu tiên **inventory chính xác – không oversell**
- Có cart, checkout, order, tracking
- Hoàn thành trong **2 tuần**

---

### 1.2 Xác định Scope (2 tuần)

### ✅ MUST-HAVE (Bắt buộc làm – Phase 1)

| Nhóm | Tính năng |
| --- | --- |
| Catalog | - Xem danh sách sản phẩm (pagination)- Lọc theo loại, giá- SKU (size, màu) |
| Cart | - Thêm / sửa / xóa item- Check tồn kho sơ bộ |
| Inventory | - Hold stock khi checkout (10–15 phút)- Xử lý race condition “last item” |
| Checkout | - Tạo đơn hàng- COD- Chuyển khoản (manual) |
| Order | - Trạng thái đơn hàng- Rollback stock khi hủy |
| Tracking | - Link tracking không cần login |
| Email | - Gửi email xác nhận đơn |
| Admin | - Xem danh sách đơn- Đổi trạng thái đơn |

---

### ⚠️ NICE-TO-HAVE (Nếu còn thời gian)

| Tính năng | Ghi chú |
| --- | --- |
| SePay Webhook thật | Có thể giả lập |
| Cache catalog | Tối ưu sau |
| Rate limit | Không critical |
| Audit log | Phase sau |

### 1.3 Gap Analysis (Email vs Thực tế kỹ thuật)

| Yêu cầu từ Email | Thực tế kỹ thuật |
| --- | --- |
| “Giữ hàng khi checkout” | Cần Redis + Reservation logic |
| “Không bán quá số” | Phải xử lý atomic / lock |
| “SePay tự động” | Cần webhook, verify signature |
| “Xong 2 tuần” | Không thể làm full payment  |

👉 **Nhận định:**

Email mô tả **business need**, chưa phản ánh:

- Độ phức tạp inventory concurrency
- Hạ tầng cần thiết (Redis, background job)
- Testing race condition

---
